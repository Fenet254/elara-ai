# My Story

If someone asked me to describe my journey in one sentence, I would say that it has always been driven by curiosity.

I was never satisfied with simply using technology. Whenever I used a website, a mobile application, or later an AI system, I found myself asking questions about what happened behind the scenes.

At around fourteen years old, those questions became much stronger.

I remember wondering things that most people probably never thought about.

How does clicking a hyperlink suddenly open another page?

How does a website know who I am after I log in?

How does it remember me the next day?

How does Google find information so quickly?

Years later another question joined the list.

How does ChatGPT understand what people ask and generate meaningful responses?

Those questions became much more interesting than simply using the software itself.

Instead of accepting technology as magic, I wanted to understand it.

That curiosity eventually became the reason I entered software engineering.

---

# My First Programming Experience

My first programming language was C++.

I learned it during Grade 10, mainly through YouTube.

Like many beginners, my first successful program printed:

Hello World.

To many experienced programmers that might sound insignificant.

To me, it felt like I had created something completely new.

I still remember how excited I was when it finally worked.

I literally jumped because I felt like I had become a real programmer.

Looking back, that tiny program represented something much bigger.

It was proof that I could tell a computer what to do.

It was the first moment where software stopped being something made by other people and became something I could create myself.

---

# Learning Without a Teacher

Most of my early learning happened independently.

Whenever I became interested in a topic, I usually started searching for YouTube tutorials.

If something was still confusing, I searched Google.

If it still didn't make sense, I searched again.

I repeated that process many times.

I never expected programming to become easy.

Instead, I expected myself to improve through repetition.

That mindset has stayed with me ever since.

Even today, when I encounter unfamiliar technologies, my instinct is still to research, experiment, test, and understand.

---

# The Calculator Project

After learning the basics of C++, I wanted something slightly more difficult than printing text.

Like many beginner programmers, I decided to build a calculator.

It took approximately two weeks.

The calculator itself was simple.

Addition worked.

Subtraction worked.

Multiplication worked.

Division became the difficult part.

At that stage of my journey, even getting one operation to work correctly felt like solving a major engineering problem.

Instead of giving up, I watched tutorials again.

I searched Google.

I compared examples.

Eventually it worked.

That experience taught me two lessons that continue influencing me today.

Practice matters more than talent.

Nothing is impossible if I continue learning.

---

# Discovering Web Development

Once I became comfortable writing simple programs, another question appeared.

How are websites actually built?

That curiosity naturally pulled me toward web development.

I started learning HTML.

Then CSS.

Then JavaScript.

Later I moved into backend development.

Each technology answered another question I had been asking for years.

HTML explained how webpages were structured.

CSS explained how they looked.

JavaScript explained how they became interactive.

Backend development explained how websites remembered users and stored information.

For the first time, the internet stopped feeling mysterious.

I could finally see how everything connected.

---

# Building My First Website

My first website was a simple To-Do application.

Compared to my current projects, it was extremely small.

However, it represented an important milestone.

Users could:

- Add tasks.
- Edit tasks.
- Delete tasks.
- Mark tasks as completed.

At that stage, refreshing the browser erased everything because I had not yet learned persistent storage.

Although the application itself was simple, it introduced many concepts.

Connecting buttons.

Handling events.

Updating the interface.

Manipulating the DOM.

Making different parts of the application communicate with each other.

Those concepts seemed difficult at first.

Eventually they became natural.

---

# Understanding the Backend

Frontend development answered many questions.

Backend development answered even more.

One project that significantly improved my understanding was a login and registration system.

Building authentication helped me finally understand something I had wondered about for years.

How do websites remember users?

Instead of simply using login systems, I was building one.

That project introduced me to:

Database design.

Authentication.

Password hashing.

Sessions.

JWT.

REST APIs.

Server-side programming.

Debugging authentication problems forced me to understand security concepts instead of blindly copying code.

---

# Learning Beyond Tutorials

At the beginning of my journey, tutorials were extremely important.

Over time, however, something changed.

Instead of asking,

"What tutorial should I follow?"

I started asking,

"What problem do I want to solve?"

That shift completely changed how I learned.

Tutorials became references.

Documentation became more valuable.

Experimentation became more frequent.

I spent more time reading error messages.

More time debugging.

More time testing ideas.

Eventually I reached a point where building projects without following a tutorial became normal.

That was one of the moments where I truly felt I had grown as a developer.

---

# Becoming Interested in Artificial Intelligence

Artificial Intelligence did not suddenly appear in my journey.

It grew naturally from the same curiosity that had always driven me.

I had already spent years trying to understand software.

Now I wanted to understand intelligence.

Seeing computer vision systems recognize objects fascinated me.

Watching machine learning models make predictions raised entirely new questions.

How does a model learn?

How does it recognize patterns?

How can mathematics become intelligence?

Then systems like ChatGPT became widely available.

Instead of simply using them, I wanted to understand how they worked internally.

That curiosity eventually led me toward machine learning, deep learning, natural language processing, and AI engineering.

---

# My Current Direction

Today I continue exploring different areas of software engineering.

However, AI has become the area where I spend most of my energy.

I enjoy combining software engineering principles with machine learning research.

Rather than viewing web development and AI as separate disciplines, I see them as complementary.

Building intelligent software requires both.

One teaches how to build reliable systems.

The other teaches how to make those systems intelligent.

Together they create opportunities to solve problems that traditional software cannot.

---

# Looking Back

When I look back at my journey, I do not think the biggest milestones were learning a new language or completing another project.

The biggest milestones were changing the kinds of questions I asked.

At first I asked:

"How do I write code?"

Later I asked:

"How do websites work?"

Then:

"How do distributed systems communicate?"

Then:

"How does artificial intelligence learn?"

I believe that as long as I continue asking better questions, I will continue becoming a better engineer.

For me, software engineering has never been about collecting programming languages.

It has always been about understanding increasingly complex systems.

That curiosity continues driving every project I build today.
