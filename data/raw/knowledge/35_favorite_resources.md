# Favorite Resources

## Introduction

People often ask me where I learn programming and artificial intelligence.

The truth is that I don't rely on a single resource.

Every resource has different strengths.

Some are better for learning fundamentals.

Some are better for solving real problems.

Others are better for staying updated with new technologies.

Over time I have developed a learning ecosystem that combines documentation, videos, research papers, open-source projects, and hands-on practice.

---

# Official Documentation

If I could recommend only one learning resource, it would be official documentation.

Documentation explains not only how to use a technology but also why it works the way it does.

Whenever I begin learning something new, documentation is usually the first place I visit.

Some documentation I frequently read includes:

- Python Documentation
- MDN Web Docs
- Node.js Documentation
- Express Documentation
- React Documentation
- Vue Documentation
- FastAPI Documentation
- TensorFlow Documentation
- PyTorch Documentation
- MongoDB Documentation
- Git Documentation

Reading documentation has become one of the most valuable habits I have developed.

---

# YouTube

YouTube played a major role in my early learning journey.

It was where I learned many programming fundamentals.

Some tutorials introduced me to programming concepts that later became the foundation for much larger projects.

Today I still use YouTube, but differently.

Instead of copying projects step by step, I use videos to understand concepts before building my own implementations.

---

# Google

Search engines remain one of my daily learning tools.

Whenever I encounter unfamiliar concepts, error messages, or technologies, searching for reliable information often provides useful starting points.

Learning how to search effectively is an underrated engineering skill.

---

# GitHub

GitHub is one of my favorite learning platforms.

Instead of only publishing my own projects, I enjoy exploring how other developers organize their code.

Open-source projects teach:

- Project structure.
- Naming conventions.
- Software architecture.
- Documentation.
- Engineering practices.

Reading other people's code has improved the way I write my own.

---

# Research Papers

As my interest in artificial intelligence grew, I started reading research papers.

Although research papers can be challenging, they provide insight into how new ideas are developed.

They also encourage thinking beyond tutorials and production code.

Research has helped me better understand experimentation and continuous improvement.

---

# AI Assistants

Modern AI assistants have become valuable learning companions.

I use them to:

- Understand unfamiliar concepts.
- Explore different approaches.
- Explain technical ideas.
- Brainstorm solutions.
- Compare technologies.

However, I always try to verify important information through documentation or experimentation.

AI is most valuable when combined with critical thinking.

---

# Stack Overflow and Technical Communities

When debugging difficult problems, community discussions are often helpful.

Reading how other engineers approached similar challenges exposes me to different ways of thinking.

Even when I do not use the exact solution, understanding multiple perspectives improves my own problem-solving ability.

---

# Open Source Communities

Open-source communities demonstrate how experienced engineers collaborate.

Watching discussions, pull requests, issue tracking, and project organization has taught me many engineering practices that go beyond writing code.

---

# Learning Through Projects

More than any website or book, projects have taught me the most.

Every project introduces:

- New technologies.
- New debugging challenges.
- Better engineering habits.
- Better architectural thinking.

Building software forces learning in ways that passive reading cannot.

---

# Learning Through Internships

My internships have been another major source of learning.

Working with mentors and experienced engineers exposed me to professional workflows, debugging strategies, collaboration, and engineering discipline.

Real-world engineering teaches lessons that are difficult to gain from tutorials alone.

---

# Keeping Up With Technology

Technology changes quickly.

To stay current, I regularly:

- Read documentation updates.
- Explore new frameworks.
- Experiment with emerging AI tools.
- Follow engineering discussions.
- Build small prototypes with unfamiliar technologies.

Continuous learning has become part of my routine.

---

# My Favorite Way to Learn

If I summarize my learning process, it usually looks like this:

1. Become curious about a topic.
2. Read official documentation.
3. Watch a few explanations if needed.
4. Build a small project.
5. Make mistakes.
6. Debug carefully.
7. Improve the implementation.
8. Apply the knowledge in larger projects.

That cycle has helped me learn almost every technology I use today.

---

# Resources I Recommend to Beginners

For someone starting software engineering, I would recommend:

- Official Documentation
- MDN Web Docs
- GitHub
- YouTube
- Python Documentation
- Stack Overflow
- Open-source projects
- Building personal projects

Most importantly, I would recommend building something.

Projects teach lessons that no tutorial can fully provide.

---

# Final Thoughts

I believe the best engineers are lifelong learners.

No single course, book, or tutorial is enough.

Growth comes from combining different learning resources with consistent practice and curiosity.

For me, learning is not an activity that eventually ends.

It is a habit that continues throughout my engineering journey.
